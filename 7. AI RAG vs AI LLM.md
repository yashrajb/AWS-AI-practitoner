# RAG vs Fine-Tuning vs Document Upload Q&A

## Why This Topic Causes Confusion

Many learners think:

```text
RAG = Upload documents and ask questions

Fine-Tuned LLM = Upload documents and ask questions
```

From a user's point of view, both seem identical because in both cases:

```text
User uploads document
        ↓
User asks question
        ↓
AI answers
```

However, the way the AI obtains the answer is completely different.

---

# Core Difference

## Fine-Tuning

Fine-tuning teaches the model information during training.

```text
Documents
      ↓
Training
      ↓
Knowledge Stored Inside Model
      ↓
Answers Generated From Memory
```

The information becomes part of the model's learned parameters (weights).

### Think of Fine-Tuning As

```text
Studying and memorizing a textbook
before an exam.
```

During the exam:

```text
No books allowed.
Use memory only.
```

---

## RAG

RAG does NOT teach the model new knowledge permanently.

Instead:

```text
Documents
       ↓
Stored Separately
       ↓
Retrieved When Needed
       ↓
Sent To LLM
       ↓
LLM Generates Answer
```

The model reads the relevant information at runtime.

### Think of RAG As

```text
Open-book exam.
```

During the exam:

```text
Question
    ↓
Open textbook
    ↓
Find answer
    ↓
Respond
```

---

# How Fine-Tuning Works

Suppose a bank wants a chatbot.

### Training Data

```text
Question:
What is a fixed deposit?

Answer:
A fixed deposit is...
```

```text
Question:
What is a recurring deposit?

Answer:
A recurring deposit is...
```

Thousands of examples are used.

---

## After Fine-Tuning

User asks:

```text
What is a fixed deposit?
```

Model replies from learned knowledge.

It does NOT search documents.

It uses:

```text
Knowledge stored
inside model weights.
```

---

# Fine-Tuning Problem

Suppose the model learned:

```text
Home Loan Rate = 6%
```

Later:

```text
Home Loan Rate = 7%
```

If no retraining occurs:

User asks:

```text
What is the current home loan rate?
```

Model may still answer:

```text
6%
```

because that is what it remembers.

---

# How RAG Works

Suppose the bank stores:

```text
Loan Policy.pdf
Interest Rates.pdf
Mortgage Guide.pdf
```

inside a Knowledge Base.

User asks:

```text
What is the current home loan rate?
```

System performs:

```text
Search Knowledge Base
        ↓
Find Interest Rate Document
        ↓
Retrieve Paragraph
        ↓
Add To Prompt
        ↓
LLM Generates Response
```

The model never memorized the rate.

It simply reads the policy document.

---

# Successful RAG Example

Knowledge Base contains:

```text
Current Home Loan Rate = 7%
```

User asks:

```text
What is the home loan rate?
```

Retrieved document:

```text
Current Home Loan Rate = 7%
```

Response:

```text
7%
```

Correct.

# Important Misconception

## Myth

```text
RAG always gives correct answers.
```

### Reality

```text
RAG can only be as good as
the information it retrieves.
```

---

# RAG Failure Scenario

Suppose bank policy changes:

```text
Old Rate = 6%
New Rate = 7%
```

But nobody updates the Knowledge Base.

RAG retrieves:

```text
Old Policy
Rate = 6%
```

The model answers:

```text
6%
```

Still wrong.

---

# Important Learning

RAG solves:

```text
Knowledge Update Problem
```

It does NOT solve:

```text
Bad Data Problem
```

---

# Fine-Tuning vs RAG Update Process

## Fine-Tuning Update

When policy changes:

```text
Collect New Data
        ↓
Train Again
        ↓
Evaluate
        ↓
Deploy Again
```

May take days or weeks.

---

## RAG Update

When policy changes:

```text
Update PDF
        ↓
Re-index Knowledge Base
        ↓
Done
```

May take minutes.

This is the biggest advantage of RAG.

---

# What Happens When I Upload a PDF to ChatGPT?

Many modern AI systems use RAG internally.

You upload:

```text
AWS_Guide.pdf
```

Ask:

```text
What is Amazon Bedrock?
```

System performs:

```text
Extract PDF Content
        ↓
Create Embeddings
        ↓
Store Chunks
        ↓
Retrieve Relevant Sections
        ↓
Send Context To LLM
        ↓
Generate Answer
```

The model is NOT retrained.

The document is only used temporarily.

---

# Why Enterprises Prefer RAG

Organizations frequently update:

- Policies
- Procedures
- Product information
- Regulations
- Technical documentation

Examples:

```text
HR Policies
Travel Policies
Legal Policies
Banking Regulations
Medical Guidelines
```

These documents change regularly.

Retraining every time would be expensive.

RAG allows organizations to:

```text
Update Document
        ↓
AI Uses New Information
```

without retraining.

# When Should You Use Fine-Tuning?

Use Fine-Tuning when you want to teach:

### Behavior

Examples:

- Company writing style
- Response format
- Customer support tone
- Legal drafting style
- Medical explanation style

### Goal

```text
Change HOW the model answers.
```

---

# Fine-Tuning Example

You want every answer:

```text
1. Professional
2. Formal
3. Regulatory-Compliant
4. Structured Format
```

Fine-tuning is appropriate.

---

# When Should You Use RAG?

Use RAG when you want the model to access:

### Dynamic Knowledge

Examples:

- Policies
- FAQs
- Wikis
- Product Catalogs
- Internal Documentation
- Regulations

### Goal

```text
Change WHAT the model knows.
```

# Ultimate Interview Answer

> **Fine-tuning teaches knowledge or behavior to the model by updating its weights, whereas RAG keeps knowledge outside the model and retrieves relevant documents at query time. Fine-tuning is best for changing how a model behaves, while RAG is best for providing current, private, or frequently changing information. RAG does not guarantee correctness because it is still dependent on the quality and freshness of the retrieved documents. Most enterprise AI systems combine both Fine-Tuning and RAG to achieve the best results.**
