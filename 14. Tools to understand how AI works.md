# Tools to Understand How AI Works (AI Transparency & Explainability)

> As AI models become more powerful, organizations need ways to understand:
>
> - What a model does
> - How it was trained
> - What data it used
> - What limitations it has
> - Whether it can be trusted
>
> These are called **AI Transparency Tools**.
>
> Think of them as:
>
> ```text
> Documentation + Explainability + Governance
> ```
>
> for AI systems.

---

# Why AI Transparency Matters

Imagine a bank uses an AI model for loan approvals.

A customer asks:

```text
Why was my application rejected?
```

If the organization cannot answer:

- Trust decreases
- Compliance risks increase
- Auditing becomes difficult

Therefore organizations need:

```text
Transparency
Documentation
Traceability
Governance
```

---

# Amazon SageMaker Model Cards

## What Are Model Cards?

Amazon SageMaker Model Cards are structured documents that describe an ML model.

Think of them as:

```text
Passport / ID Card
for an AI model
```

Just as a person's ID card contains information about the person,

a Model Card contains information about the model.

---

# Why Model Cards Exist

Without documentation:

```text
Team builds model
        ↓
6 months later
        ↓
Nobody remembers:
- Why it was created
- Which data was used
- What limitations exist
```

Model Cards solve this problem.

---

# Information Stored in a Model Card

---

## 1. Model Purpose

Describes:

```text
Why was the model built?
```

---

### Example

```text
Purpose:
Predict customer churn
for a telecom company.
```

---

## 2. Performance Metrics

Describes:

```text
How well does the model perform?
```

Examples:

- Accuracy
- Precision
- Recall
- F1 Score
- AUC

---

### Example

```text
Accuracy = 96%
Precision = 94%
Recall = 92%
```

---

## 3. Intended Use Cases

Describes:

```text
When should this model be used?
```

---

### Example

A fraud detection model may be approved for:

```text
Credit card transactions
```

but not for:

```text
Loan approval decisions
```

---

## 4. Limitations

Every AI model has limitations.

A model card documents them.

---

### Example

```text
Works well for adults

Not extensively tested
on children
```

or

```text
Training data ends in 2024.
```

---

## 5. Ethical Considerations

Documents:

- Potential bias
- Fairness concerns
- High-risk usage scenarios
- Responsible AI recommendations

---

### Example

```text
Model may show lower accuracy
for elderly users.
```

This alerts stakeholders before deployment.

---

# Open Source Models

## What Are Open Source Models?

Open source models provide visibility into:

- Model architecture
- Source code
- Training procedures
- Configuration details

Developers can inspect and modify them.

```text
You use it
But cannot see inside it.
```

With an open-source model:

```text
You can inspect

improve
extend
the model.
```

# Data Transparency

## Why Data Transparency Matters

Remember:

```text
Model Quality
      ↓
Data Quality
```

If data quality is poor,

the model will likely perform poorly.

---

## What is Data Transparency?

Data transparency means documenting:

- Where data came from
- How it was collected
- How it was cleaned
- How it was transformed
- What limitations exist

---

# Key Data Information

---

## Data Sources

Example:

```text
Websites
Internal Documents
Customer Records
Research Databases
```

---

## Data Collection Methods

Documents:

```text
How data was gathered
```

Example:

```text
Survey
API
Manual Collection
Database Export
```

---

## Preprocessing Steps

Data often requires cleaning.

Documenting these steps is important.

---

### Example

Original Data:

```text
Duplicate Records
Missing Values
Invalid Entries
```

Preprocessing:

```text
Duplicates Removed
Missing Values Filled
```

---

# Data Licensing Information

Explains:

```text
Can we legally use this data?
```

and

```text
Can we redistribute it?
```

---

## Example

Dataset may allow:

```text
Research Use Only
```

but prohibit:

```text
Commercial Use
```

This information must be documented.

# Datasheets and Data Statements

These are standardized documents describing datasets.

Think:

```text
Model Card
      ↓
For Models

Datasheet
      ↓
For Data
```

---

# What Datasheets Include

- Dataset Purpose
- Collection Method
- Size
- Biases
- Limitations
- Usage Restrictions

---

# Example

Healthcare Dataset

Documentation may state:

```text
90% Adult Patients
10% Children
```

Potential limitation:

```text
May not generalize
well to children.
```

# Why Data Transparency Matters

Helps identify:

- Bias
- Data gaps
- Legal issues
- Reliability risks

before deployment.

# Licensing Frameworks

## What is Licensing?

A license is a legal agreement defining:

```text
What users can do
with data or models.
```

---

# Why Licensing Matters

Organizations must know:

```text
Can we:
- Use it?
- Modify it?
- Sell it?
- Redistribute it?
```

---

# Common Open Source Licenses

---

## MIT License

Very permissive.

Generally allows:

- Use
- Modify
- Distribute

with minimal restrictions.

---

## Apache 2.0 License

Also very permissive.

Additionally provides:

- Patent protections
- Commercial usage rights

Common in enterprise environments.

---

## Other Licenses

Examples:

- GPL
- BSD
- Creative Commons
- Proprietary Licenses

Each has different requirements.

---

# Real Example

Suppose your company finds an AI model on GitHub.

Before using it:

You must verify:

```text
Which license?
Commercial use allowed?
Modification allowed?
Redistribution allowed?
```

Ignoring licensing can create legal and compliance issues.

---

# Why Licensing Supports Responsible AI

Licensing helps:

- Protect creators
- Protect users
- Ensure attribution
- Support legal compliance
- Encourage transparency

# Real-World Scenario: AI Loan Approval System

A bank wants to deploy an AI model for loan approvals.

---

## Step 1: Choose a Model

The bank downloads an open-source model from Hugging Face.

Benefits:

```text
Can inspect architecture
Can review code
Can customize model
```

**Concept Used:**
- Open Source Models

---

## Step 2: Verify Licensing

Legal team reviews the model license.

Questions:

```text
Can it be used commercially?
Can it be modified?
Can it be deployed to customers?
```

The Apache 2.0 license permits usage.

**Concept Used:**
- Licensing Frameworks

---

## Step 3: Review Training Data

Data documents reveal:

```text
Training Data:
90% Urban Customers
10% Rural Customers
```

Potential concern:

```text
Model may perform worse
for rural applicants.
```

**Concept Used:**
- Data Transparency
- Datasheets
- Data Statements

---

## Step 4: Build and Evaluate Model

Model is trained and tested.

Results:

```text
Accuracy = 95%
Precision = 93%
Recall = 91%
```

**Concept Used:**
- Performance Metrics

---

## Step 5: Create Model Card

The bank documents:

### Purpose

```text
Predict loan approval risk.
```

### Intended Use

```text
Loan risk assessment support.
```

### Limitation

```text
Not intended to replace
human final approval.
```

### Ethical Consideration

```text
Additional monitoring required
for rural customers.
```

**Concept Used:**
- SageMaker Model Cards

---

## Step 6: Share with Stakeholders

Export Model Card as PDF.

Reviewed by:

- Compliance Team
- Risk Team
- Management
- Auditors

**Concept Used:**
- Documentation
- Governance

---

## Step 7: Production Usage

When a regulator asks:

```text
How was this model built?
```

the bank can provide:

```text
Model Card
+
Dataset Documentation
+
License Information
```

demonstrating transparency and compliance.

### One-Line Interview Answer

> **SageMaker Model Cards document a model's purpose, performance, limitations, and ethical considerations, while data transparency tools document how datasets were collected and processed.
